# Feature Specification: 工单字典字段配置

**Feature Branch**: `001-add-ticket-dictionary-field`  
**Created**: 2026-05-21  
**Status**: Draft  
**Input**: User description: "工单提交页面增加一个字段，如果选择新系统，就叫险种，如果是老系统，就叫模块，但是具体名称还可以根据系统来自定义，也就是说系统配置界面，可以按系统配置具体的中文名称。每一种名称都有对应的枚举值，所以这个可以通过词典来配置。存入到工单的时候，需要存入对应的词典编号和选项编号以及中文名。"

## Clarifications

### Session 2026-05-21

- Q: 配置后的分类字段是否必填？ → A: 始终选填，用户可以不选。
- Q: 历史工单是否需要保存字段中文名？ → A: 保存字段中文名和选项中文名。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 提交工单时选择系统相关分类 (Priority: P1)

工单提交人选择目标系统后，页面显示该系统配置的字段中文名称，并允许提交人从对应字典选项中选择一个值；若提交人选择了该字段，提交后工单保留该选择的字典编号、选项编号和中文名，便于后续处理和统计。

**Why this priority**: 这是业务人员在提交工单时获取准确分类信息的核心流程，没有该流程就无法按不同系统区分险种、模块或其他自定义分类。

**Independent Test**: 配置一个新系统字段名为“险种”并关联险种字典，再在工单提交页选择该系统，确认字段显示、选项选择和工单保存信息均正确。

**Acceptance Scenarios**:

1. **Given** 某新系统已配置字段中文名“险种”并关联险种字典，**When** 提交人选择该系统，**Then** 工单提交页显示“险种”字段并列出该字典的可选项。
2. **Given** 提交人已选择系统并选择一个字典选项，**When** 提交工单，**Then** 新工单记录包含所选字典编号、选项编号和选项中文名。
3. **Given** 提交人已选择系统但未选择分类字段，**When** 提交工单，**Then** 工单可正常提交且不保存该分类字段的字典编号、选项编号和选项中文名。
4. **Given** 某老系统已配置字段中文名“模块”并关联模块字典，**When** 提交人选择该系统，**Then** 工单提交页显示“模块”字段并列出该字典的可选项。

---

### User Story 2 - 管理员按系统配置字段名称和字典 (Priority: P2)

系统配置管理员可以在系统配置界面为每个系统设置该工单分类字段的中文名称，并指定该字段使用哪一个字典作为枚举来源。

**Why this priority**: 不同系统对同一类业务信息有不同叫法和取值范围，配置能力可以避免固定字段名造成误解，也减少后续改动成本。

**Independent Test**: 在系统配置界面修改某系统的字段中文名称和关联字典，返回工单提交页选择该系统，确认显示名称和选项来自最新配置。

**Acceptance Scenarios**:

1. **Given** 管理员打开某系统配置，**When** 设置字段中文名称并选择一个字典，**Then** 该系统保存该字段配置。
2. **Given** 某系统配置已从“模块”改为“险种”并更换字典，**When** 提交人重新选择该系统，**Then** 工单提交页显示更新后的名称和对应字典选项。

---

### User Story 3 - 查看工单时呈现已保存分类信息 (Priority: P3)

工单查看人打开已提交工单时，可以看到提交时保存的分类字段中文名和选项中文名，即使之后系统配置或字典选项发生变化，也能理解工单提交时的原始选择。

**Why this priority**: 历史工单需要保持可追溯性，避免配置或字典变更后影响既有工单的业务含义。

**Independent Test**: 提交工单后修改系统字段名称或字典选项名称，再查看原工单，确认工单展示提交时保存的中文信息。

**Acceptance Scenarios**:

1. **Given** 工单已保存分类字段和选项中文名，**When** 用户查看该工单，**Then** 页面显示该工单保存的字段名称和选项名称。
2. **Given** 系统配置或字典选项后续发生变化，**When** 用户查看历史工单，**Then** 历史工单仍显示提交时保存的中文名称。

---

### Edge Cases

- 当所选系统未配置该字段名称或字典时，工单提交页不显示该字段，且不阻止其他必填信息的提交。
- 当系统配置了字段名称但未关联可用字典时，提交页显示清晰提示，说明该系统暂不可选择该分类字段。
- 当关联字典没有可用选项时，提交页显示该字段但不提供选项，并提示联系管理员维护字典；用户仍可不选择该字段并继续提交工单。
- 当提交人已选择一个系统分类值后切换系统时，原选择应被清空，并重新展示新系统对应字段和选项。
- 当字段名称或字典选项中文名变更后，历史工单仍保留提交时保存的中文名。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在系统配置界面支持为每个系统配置一个工单分类字段中文名称。
- **FR-002**: 系统 MUST 支持为每个系统的工单分类字段关联一个字典，字典提供该字段的枚举选项。
- **FR-003**: 系统 MUST 根据工单提交页选择的系统动态显示对应的字段中文名称；例如新系统默认可配置为“险种”，老系统默认可配置为“模块”。
- **FR-004**: 用户 MUST 能够在工单提交页从所选系统关联字典的可用选项中选择一个分类值，也 MUST 能够不选择该字段并继续提交工单。
- **FR-005**: 系统 MUST 在用户选择分类值后，在工单提交时保存所选分类值对应的字典编号、选项编号和选项中文名；未选择时不得保存空白或无效分类值。
- **FR-006**: 系统 MUST 保存工单提交时展示的分类字段中文名称和所选选项中文名称，用于历史工单展示和追溯。
- **FR-007**: 系统 MUST 在用户切换所选系统时刷新分类字段名称和可选项，并清空不再适用的已选分类值。
- **FR-008**: 系统 MUST 在所选系统没有配置分类字段或字典时提供明确反馈，避免用户误以为分类信息已填写。
- **FR-009**: 系统 MUST 在查看工单时展示工单保存的分类字段中文名称和选项中文名。
- **FR-010**: 系统 MUST 保证后续系统配置或字典变更不会改变既有工单已保存的字典编号、选项编号、字段中文名和选项中文名。

### Key Entities *(include if feature involves data)*

- **系统配置**: 表示一个可在工单中选择的业务系统；包含系统标识、系统名称、工单分类字段中文名称，以及该字段关联的字典。
- **字典**: 表示一组可配置枚举值；包含字典编号、字典名称和可供选择的选项集合。
- **字典选项**: 表示字典中的单个可选值；包含选项编号、选项中文名和可用状态。
- **工单**: 表示用户提交的服务请求；包含所选系统、分类字段中文名称、字典编号、选项编号和选项中文名。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 95% 的提交人在选择系统后 2 秒内能看到正确的分类字段名称和可选项。
- **SC-002**: 管理员能够在 2 分钟内完成单个系统的分类字段名称和字典配置。
- **SC-003**: 100% 已选择该字段的工单都保存字典编号、选项编号和中文名；未选择该字段的工单可正常提交且不会保存空白或无效分类值。
- **SC-004**: 切换系统后分类字段误提交率为 0，即不会将上一个系统的分类选项保存到新系统工单中。
- **SC-005**: 历史工单在系统配置或字典名称变更后仍能展示提交时保存的中文信息，抽样验证通过率达到 100%。

## Assumptions

- 每个系统最多配置一个本次新增的工单分类字段。
- “新系统显示险种、老系统显示模块”是默认业务配置示例，实际展示名称以系统配置界面设置为准。
- 字典和字典选项已存在统一维护能力，本功能只要求能在系统配置中选择并引用字典。
- 已停用或不可用的字典选项不应出现在新工单提交选项中，但历史工单仍保留已保存信息。
- 工单提交页已有系统选择流程，本功能基于所选系统展示新增分类字段。
